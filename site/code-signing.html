Code signing policy

How NiceGit's Windows downloads are signed, and what the app sends over the network.

Signing

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

From the first release signed this way, the Windows app (nicegit.exe) and installer (.msi) show SignPath Foundation as their publisher. Releases before then are unsigned.

  • Only files built by NiceGit's release workflow on GitHub-hosted runners are signed, from a version tag on the main branch of the public repository.
  • Every release is approved by hand before it is signed and published.
  • The macOS app is signed with an Apple Developer ID and notarized by Apple.
  • Each release lists SHA256SUMS.txt, so a download can be checked against what was published.

Team roles

  • Committers and reviewers: Daniaal Nadir, the project's maintainer. Changes reach main through pull requests that pass the automated tests on macOS, Windows and Linux.
  • Approvers: Daniaal Nadir.

Everyone in these roles uses multi-factor authentication for GitHub and SignPath.

Privacy

NiceGit will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it, with one exception you can turn off:

  • Update check: once a day NiceGit asks GitHub for the latest release number. Nothing about you or your repositories is sent. Turn it off under Settings › General.

Everything else happens only when you ask for it: Git talks to the remotes you fetch from and push to, and the GitHub and GitLab command-line tools you have signed in to fetch pull requests and issues. NiceGit has no account, analytics or crash reporting.
